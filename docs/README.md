# Documentación

Cada carpeta corresponde a un entregable del curso. Usar archivos Markdown (`.md`) o PDF.

| Carpeta | Qué debe haber | Entrega |
|---|---|---|
| `sprint-0/` | Integrantes y roles, acuerdos de trabajo, actividades definidas en el sprint cero, Definition of Done | 1 |
| `backlog/` | Product Backlog con mín. 20 historias ("Como [rol], quiero [funcionalidad], para [beneficio]"), puntos de historia (Planning Poker), prioridad, criterios de aceptación, plan de sprints y tareas por integrante | 1 |
| `diseno/` | Link a los prototipos de Figma, diagrama entidad-relación, diagrama de arquitectura | 1 y 2 |
| `api/` | Documentación de los endpoints REST (Swagger/OpenAPI o Postman) | 2 |
| `pruebas/` | Casos de prueba (entrada, resultado esperado, resultado obtenido) y resultados de las pruebas unitarias y funcionales | 2 |
| `manuales/` | Manual de instalación, manual de usuario para cada actor, manual del desarrollador | 2 |

Cada vez que se cierra un sprint, actualizar el backlog y registrar en `sprint-0/` (o en una
carpeta `sprint-N/`) el resultado de la Sprint Review y la Retrospective.
